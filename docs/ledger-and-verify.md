# Ledger, bundles, and offline verification (M1.4)

Implements `spec/03` §5 (durable log), §8 (bundles), §10 (verifier).

## On-disk layout

```
<ledger>/
  entries.jsonl      one canonical DSSE-envelope line per record, seq order
  hashes.bin         32-byte RFC 6962 leaf hash per entry (same order)
  sessions/<id>.idx  text index: "<log_index> <eseq>" lines per session
  checkpoint.txt     latest signed checkpoint (x/mod note)
```

## Writes

`Open` creates the dir and append-only files; `Append(line)` decodes the
envelope, writes the line + leaf hash, and returns only after the record is
covered by an fsync. A group-commit flusher issues at most one fsync every
2 ms; `Append` blocks on a condvar until `durable >= seq`. Single writer:
`Append` serializes internally; a `Ledger` is the only writer.

## Recovery

On open, `entries.jsonl` is scanned line-by-line; each complete line's stored
leaf hash is compared against `hashes.bin` and the record is re-validated.
Only a torn final tail (bad line, bad hash, or hash-count mismatch) is
truncated; intact records are never rewritten. Session indexes are rebuilt
deterministically from the surviving lines.

## Checkpoints and indexes

`Checkpoint()` writes a signed checkpoint (`countersign.dev/log/<id>`) for the
current tree size/root. `SessionIndices` maps every session's `(index, eseq)`
pairs from the `.idx` files.

## Bundles

`ExportBundle(w)` writes a deterministic tar: sorted member names, fixed
mode/mtime/uid/gid — byte-identical across exports. Members: `entries.jsonl`,
`hashes.bin`, `checkpoint.txt`, `sessions/*.idx`, `keys.json` (manifest).
`ReadBundle` enforces the required-member set and rejects extras.

## `csverify` — V1–V11 + V15

`csverify <bundle> --keys keys.json` runs fully offline (no network, no
ledger-dir access) and exits 0 only for `CLEAN`/`CLEAN_WITH_DENIALS`.

- V1 tar well-formed, required members present → `E_BUNDLE`
- V2 DSSE + schema validation → `E_SCHEMA`/`E_DSSE`
- V3 signatures + manifest role/validity → `E_SIG`/`E_KEY`
- V4 subject/session fields → `E_SESSION`/`E_SUBJECT`
- V5 emitter chains (eseq/eprev/seal) → `E_CHAIN`
- V6 checkpoint signature + log-key origin → `E_CHECKPOINT`
- V7 inclusion proofs, increasing `log_index` → `E_INCLUSION`/`E_ORDER`
- V8 first record `session.open`, policy/contracts digests → `E_OPEN`/`E_POLICY`
- V9 `world.closed` then final controller `session.seal` → `UNSEALED`
- V10 seal heads / final sequence → `E_SEAL`
- V11 references, ordering, structure → `E_STRUCTURE`
- V15 warnings: dangling effects, unclean emitters, observer gaps, unparsed
  intents, partial commits, unknown apply outcomes, undo conflicts.

Golden bundles for every verdict path live in `test/vectors/evidence/` and are
regenerated by `tools/genvectors`.
