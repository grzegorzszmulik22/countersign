# Evidence format (Go implementation)

`internal/evidence` implements the record format of `spec/03-evidence-format.md`:
each record is a one-line DSSE v1 envelope whose payload is an in-toto
Statement v1 wrapping a Countersign predicate.

## Layout

- `envelope.go` — `Envelope`, `Signature`, `PAE` (the signing input), canonical
  marshal/unmarshal. Exactly one signature; `payloadType` is fixed to
  `application/vnd.in-toto+json`; `payload` and `sig` are standard base64 and
  non-canonical encodings are rejected.
- `statement.go` — `Statement` with `_type`/`predicateType` enforced,
  `SessionSubject` (`countersign:session:<id>` + sha256 of the session id).
- `record.go` — `Record` (the common predicate fields) and a type registry for
  the 34 record bodies of 03 §4. `MarshalRecordLine`/`DecodeRecordLine` cover
  the whole record→line pipeline.
- `bodies_*.go` — the body structs. `cs` struct tags drive the schema
  generator and test samples only.
- `strict.go` — the strict JSON gate: UTF-8 only, no duplicate keys, valid
  escapes/surrogate pairs, RFC 8259 numbers, depth-bounded; then a typed
  decode with unknown fields rejected. Every decode path goes through it.

## Invariants

- Encode is deterministic: field order, sorted map keys, no HTML escaping,
  `RawMessage` compacted. Encode → decode → encode is byte-identical.
- `?` fields of 03 §4 encode as explicit `null`; all fields are emitted.
- Required list/map fields never encode as `null` (normalized at marshal).
- Version `v` is `1`; anything else is rejected.
- Semantic rules (enums, formats) live in the JSON Schemas, not the decoder.

## JSON Schemas

`api/schema/records/<type>.json` is generated by `tools/schemagen` from the
Go types and `cs` tags (`go run ./tools/schemagen api/schema/records`).
`api/schema/records/_common.json`, `api/schema/envelope.json` and
`api/schema/statement.json` are hand-written. Check C1.1.4 enforces the
type↔schema bijection and that committed schemas match the generator output.
